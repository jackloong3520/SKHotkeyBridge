# 发布到 GitHub 操作指南

## 首次发布

```bat
cd D:\work\对拷线APP解析\repo

git init
git add .
git commit -m "feat: Mac KM Link 对拷线快捷键桥接（适配 V1.0.1325.47R）"

git remote add origin https://github.com/<你的用户名>/SKHotkeyBridge.git
git branch -M main
git push -u origin main
```

> 若仓库已存在，只需 `git remote add origin ...` 后推送。

## 发布带 EXE 的版本

GitHub Actions 会在以下两种情况自动编译并发布 Release：

### 情况一：推送标签（有命令行时）

```bat
git tag v1.0.0
git push origin v1.0.0
```

### 情况二：网页手动触发（无需命令行）

1. 打开仓库 → **Actions** 标签页
2. 左侧选 **Build Windows EXE**
3. 点右侧 **Run workflow**
4. 标签名填 `v1.0.0`，点绿色按钮确认

工作流完成后会自动生成 Release 并附上：

- `SKHotkeyBridge.exe`
- `SKHotkeyBridge.ini`
- `SHA256.txt`（供他人校验）
- `使用说明.md`

> 这是本项目分发成品 EXE 的**唯一正规途径**。EXE 不提交进 git 仓库历史。

## 固定下载直链

Releases 提供永久稳定的 latest 直链，重装系统或换电脑后直接访问即可下载最新版：

```
https://github.com/jackloong3520/SKHotkeyBridge/releases/latest/download/SKHotkeyBridge.exe
https://github.com/jackloong3520/SKHotkeyBridge/releases/latest/download/SKHotkeyBridge.ini
```

仓库中的 `install.ps1` 用的就是这组直链，可一条命令完成"下载 + 安装 + 开机启动"。

## 发布前检查清单

- [ ] `SKHotkeyBridge.ini` 中的参数与目标版本一致（窗口类、两个命令号、托盘消息号）
- [ ] `README.md` 顶部"适用版本"表格已核对
- [ ] 本地跑过 `SKHotkeyBridge.exe --self-test` 与 `--check-target`
- [ ] 实测过一键同步的完整往返（全开 → 全关 → 全开）
- [ ] 仓库中**不包含**原版程序的任何二进制文件（`.gitignore` 已排除 `*.exe`，但已编译的 Release 产物只应走 Releases，不要提交到仓库）
- [ ] README 与 Release 页面都提供了 EXE 的 SHA-256
- [ ] 未附带任何单位内部信息、人名、设备编号或敏感路径

## 合规提醒

公开仓库发布前请确认：

- 仓库中不含原厂程序、许可证文件、密钥或受版权保护的资源
- 提交记录中不含单位名称、内网地址、人员名单等敏感信息（可用 `git log -p` 全文检查一遍）
- 头像、昵称、提交邮箱等个人信息按个人意愿处理（可用 GitHub 的 noreply 邮箱）

- 后续若新增适配版本，建议在 README 的适用版本表格中逐条列出实测过的版本
