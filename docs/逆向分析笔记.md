# 逆向分析笔记（Mac KM Link V1.0.1325.47R）

记录本工具所依赖的关键参数是如何探明的，以及哪些思路被证明走不通。便于他人复核，也便于适配其他版本。

---

## 一、目标识别

### 1. 入口与实际载荷

`SKLoader.exe` 只是一个加载器，真正的核心程序被释放到：

```
%APPDATA%\OTi\MacKMLink1325\FunctModules\{8AEC7F86-B5F4-499b-9ACE-203F46E4469D}\MacKMLink.exe
```

版本标识来自两个位置，均为 `1.0.1325.47`：

- `Deployment\Config\LoaderMenifest.xml` → `<loader uuid="..." version="1.0.1325.47">`，`OEMInfo CompanyID="OTi" ProductName="MacKMLink1325"`
- `autorun.inf` → `ISOVersion=1.0.1325.47`

### 2. 窗口与命令号

枚举该进程的窗口，找到隐藏窗口类 `SmartKMCCableWinClass`。右键托盘图标弹出菜单后，用 `MN_GETHMENU`（`0x01E1`）取菜单句柄，逐项读取：

| 命令 ID | 菜单文字（状态 A） | 菜单文字（状态 B） |
|---|---|---|
| **32776** | 暂时关闭鼠标键盘控制 | 开启鼠标键盘控制 |
| **32777** | 暂时关闭剪贴簿分享 | 开启剪贴簿分享 |

向该窗口 `PostMessage(WM_COMMAND, id, 0)` 即可完成切换 —— **等价于手动点击菜单项**，且无需弹出菜单。

## 二、状态读取：三个死胡同

要实现"一个键同时控制两项"，必须先读到每项当前状态。以下三条路都试过，均不可行。

### 死胡同 1：配置文件 / 注册表

程序**不把开关状态落盘**。遍历 `%APPDATA%\OTi` 下全部文件，对比切换前后的大小与修改时间，无任何变化。

### 死胡同 2：托盘提示文字

用 `Shell_NotifyIconGetRect` 定位托盘图标后读取 tooltip，提示文字**不随开关状态变化**，无利用价值。

### 死胡同 3：缓存菜单句柄

菜单**每次右键都重新创建**，关闭后句柄立即失效，无法缓存复用。必须每次重新弹出。

---

## 三、可行方案：程序化弹出菜单读取

### 1. 托盘回调消息

探明目标程序内部托盘回调消息为 `0x8001`，图标 ID 为 `0`：

```c
PostMessage(hwnd, 0x8001, 0, WM_RBUTTONUP);   // 0x8001 = TrayMessage, 0 = TrayIconId
```

发送后目标进程会创建菜单窗口（类 `#32768`）。

### 2. 精确定位菜单窗口

系统里 `#32768` 类窗口很多（其他程序、资源管理器等），必须按**类名 + 所属进程 PID** 双重过滤，否则会误读或误关别人的菜单。

### 3. 隐藏与关闭

- 隐藏：`SetWindowPos(popup, NULL, -30000, -30000, 0, 0, SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE)`，移到屏幕外，避免闪烁。
- 关闭：**只有 `WM_CLOSE` 可靠**（约 25 ms）。实测 `WM_CANCELMODE` 与 `EndMenu()` **均无效**，会把菜单卡死在屏幕上；失败时回退到模拟 `Esc` 按键。

整个"弹出 → 读取 → 关闭"约 20 ms。10 次连续读取压测：全部成功，零残留菜单。

### 4. 状态映射（注意是反的）

菜单显示的是**下一步动作**，不是当前状态：

| 菜单文字 | 当前状态 |
|---|---|
| 暂时关闭… | 开启中 |
| 开启… | 已关闭 |

英文界面回退规则：含 `disable` → 开启中；含 `enable` → 已关闭。

## 四、同步开关逻辑

```python
state = probe_state()               # (km, clipboard)
target = not (km or clipboard)      # 有任何一项开着就全关；全关就全开
set_both(target)                    # 只发送需要改变的那一项
if verify_after_command:
    re-probe and assert             # 校验，失败提示再按一次
```

先读状态、只发必要的命令（而非各切一次），是"两项永不失步"的关键。即便因手动操作导致状态不一致，下一次按同步键也会自动收敛。

## 五、安全边界

- 全程只使用 `PostMessage` / `SendMessage` 等公开 Win32 消息机制。
- **不修改**磁盘上的任何原程序文件（原 `SKLoader.exe` SHA-256 全程未变）。
- **不注入**目标进程，不 `WriteProcessMemory`，不开远程线程。
- 不做任何授权绕过 —— 两个菜单命令在原程序的 UI 上本就对用户开放。
- 权限检测：比较自身与目标进程的 UAC 完整性级别；目标更高级别时主动提示，避免静默失败。
